The Problem

Dietary Assessment Is a Bottleneck in Precision Medicine

  • Manual food logging is burdensome and poorly sustained in long studies
  • Self-reported intake often underestimates calories and misclassifies foods
  • Multi-subject dining settings need per-participant tracking from a single camera
  • Health research demands data sovereignty — photos and intake data cannot leave the institution lightly

What researchers need

  • Passive, objective meal documentation
  • Structured, exportable dietary phenotypes
  • Local processing with optional cloud AI
  • Repeatable fixed-camera lab deployments

SmartDining addresses the data collection layer — turning meal photos into structured intake signals for downstream precision-medicine pipelines.

Overview

What Is SmartDining?

A local-only web application that captures meal photos, runs vision AI to identify foods and estimate visible portions, and visualizes dietary patterns over time.

Architecture

Privacy-First, Local-First Design

🔒

Data stays local

Meal photos, analysis results, settings, and device telemetry are stored on your machine — SQLite database and JSON cache files. No cloud photo uploads.

🔑

User-controlled AI

Vision analysis calls Google Gemini or Anthropic Claude using your API keys. Only image data sent to AI providers — never to a SmartDining cloud.

📤

Research-ready export

Structured JSON export of all analysis results for downstream pipelines — EHR integration, cohort analytics, or nutrition validation studies.

Research fit: Ideal for IRB-constrained environments where meal imagery must remain on-premises while still leveraging state-of-the-art vision AI.

Hardware Setup

Overhead Phone Camera — Fixed Dining Rig

Fixed overhead mount

Android phone secured above the table with a consistent downward angle. Same viewpoint every meal enables zone mapping and repeatable analysis.

Remote control

SmartDining on a lab PC triggers the shutter via ADB over Wi‑Fi or USB. Photos are pulled locally — no cloud upload.

Zone regions

Dashed rectangles define per-seat and shared-dish areas on the table surface, applied automatically to every captured frame.

Innovation

Zone-Based Multi-Subject Analysis

Draw named rectangular zones on a reference photo — the same layout applies to every image from your fixed overhead camera.

  • Seat 1, Seat 2, Shared dish — per-participant intake from one frame
  • Each zone cropped server-side with Sharp → separate AI call → merged results
  • Gallery lightbox shows zone overlays and per-zone result tabs
  • Normalized coordinates — annotate once, analyze forever

Use case: family / cohort dining study

A single overhead camera captures a shared table. Zones isolate each participant's plate area for independent dietary phenotyping without separate cameras per subject.

Capture Pipeline

Passive Meal Documentation

📁

Manual drop

Drop JPG, PNG, WebP, or MP4 files into the local data/ folder. Ideal for existing study archives.

📸

One-shot snap

Android phone connected via USB or Wi‑Fi ADB. Remote shutter fires from the web UI; photo pulled to local storage.

🎬

Scheduled recording

Configure interval (5–600 s) and max duration (1–240 min). Frames saved to session folders with playback and automatic phone cleanup.

24/7 lab deployments: Charge control stops charging at 80% and resumes at 20%. Phone health monitoring tracks battery, temperature, storage, and GPS for long-running research rigs.

AI Pipeline

Clinical Nutrition Assistant

Vision AI is prompted as a clinical nutrition assistant — identifying foods and estimating actual visible portion weight in grams, not standard serving sizes.

  • Splits compound items (e.g., rice and beans → separate line items)
  • Flags composite dishes (lasagna, burrito) vs. separable items
  • Optional meal context ("half portion eaten") improves accuracy
  • Batch processing for entire galleries

Planned: USDA nutrient database lookup after AI identification — a more defensible two-stage pipeline for clinical research.

Current output schema (v2)

{ "items": [ { "name": "grilled chicken", "estimated_weight_grams": 120, "count": 1, "is_composite": false }, { "name": "steamed broccoli", "estimated_weight_grams": 85, "is_composite": false } ], "schema_version": 2 }

Analytics

From Photos to Dietary Phenotypes

  • Weight timeline — estimated grams over time from filename timestamps
  • Result format mix — tracks schema evolution across study phases
  • API cost tracking — token usage and estimated USD per call for study budgeting

JSON export

One-click export of all cached analysis results — ready for:
